Definitions and decision rules
  • Plan clock. For the current plan date, use the live clock in plan.timezone. For another date, use plan.asOf and label the view “Snapshot”. Compare times within the plan date.
  • Done. The existing completion mark for a step ID is authoritative. Recalculate the summaries after each mark or undo. Count only IDs present in the loaded plan.
  • Overlap. A warning, not a plan error. A timed you step that intersects another timed you step or a you break is marked “Overlap”. Touching ranges do not count.
  • Blocked. At least one step in after lacks a completion mark. Show the open prerequisites by title and lane. A planned end time passing never clears a prerequisite.
  • Scheduled. A step timed later in the plan day is upcoming. A step with on belongs under Later. If an upcoming step has an open prerequisite, show that status in its detail.
  • Ready. A timed you or agent step has reached its planned start, has no open prerequisites, and is unfinished. Choose the earliest planned start per owner. Break ties with the order in plan.steps. A ready agent task is eligible for a handoff.
  • Waiting on. An unfinished other step has reached its planned start and has no open prerequisites. Use the lane name to identify the person or team. Choose the earliest open wait and name the first unfinished task it directly unblocks, if one exists.
  • Empty summaries. If no task qualifies, distinguish “Starts later today”, “Blocked”, and “Nothing left today”. Keep each owner’s state independent. Show Later tasks in their own section.
Palette and typography

Use system sans for titles and labels. Use tabular figures for times. Reserve the tinted green surface for the personal action. Use written states with color, and keep keyboard focus visibly distinct from task status.

Pair the personal, agent, and waiting text colors with their matching surfaces. Use the critical color for marked dependency paths. Keep normal text at 4.5:1 contrast or higher and focus indicators at 3:1 or higher against adjacent colors.

Acceptance cases and code boundaries
  1. Late approval at 11:05. An overdue merge still needs release approval. The personal card shows “Reply to the feedback”, the agent card shows “Draft a regression test”, and the waiting card identifies the release reviewer.
  2. Approval arrives. Mark the approval done. “Merge the release PR” becomes the personal action. Undo it. The reply returns and the wait reappears.
  3. Blocked or empty. If the reply and agent task are done, show the human merge as blocked and retain the waiting card. When every timed task is done, preserve access to the Monday task.
  4. Clock boundaries. At 09:45 each later timed task stays scheduled. At its exact start a task can become ready. When viewing a previous date, label the displayed clock as a snapshot.
  5. Plan changes and access. When a saved completion ID disappears from the plan, the visible count stays correct. At 390 px the summaries and detail fit without page scrolling sideways. A keyboard user can select a task, follow a prerequisite, mark or undo completion, and return to the selected task. The accessible task name includes the current status.
